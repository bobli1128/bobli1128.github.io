# 剪枝：让搜索跑得更快

## 搜索的瓶颈：指数爆炸

搜索树是指数级的：全排列 $n!$、子集 $2^n$。$n = 20$ 的 $2^{20} \approx 100$ 万还行，$n = 40$ 就是 1 万亿——**搜索能不能活下来，取决于能不能提前砍掉没用的分支**。

**剪枝**：在搜索树长出来之前，判断「这条分支肯定走不到答案」，**整棵砍掉不进**。剪掉一个节点，它的整棵子树就都省了——越早剪越值钱。

## 四种常用剪枝

1. **可行性剪枝**：走到一半发现已不合法（超界、资源用光），立刻返回
2. **最优性剪枝**：求最小值时，当前代价已 ≥ 已知最优解，立刻返回（继续走只会更差）
3. **排除等效冗余**：几个分支效果完全一样，只走其中一个
4. **顺序优化**：先试「更有希望」的分支，让最优解早点出现，后面的最优性剪枝更快出手

## 例题：数的划分

> **题目描述**　把整数 $n$ 分成 $k$ 份，每份不能为空，任意两种分法不考虑顺序（即 `1 1 5` 和 `1 5 1` 算同一种）。求方案数。
>
> **输入格式**　一行两个整数 $n$、$k$。
>
> **输出格式**　一个整数。
>
> **数据范围**　$1 \le n \le 200$，$1 \le k \le 6$。
>
> **样例输入 / 样例输出**
>
> ```text
> 7 3
> ```
>
> ```text
> 4
> ```
>
> 四种分法：`1 1 5`、`1 2 4`、`1 3 3`、`2 2 3`。

**思路分析**　**去重是本题的灵魂**：同样的数字组合换个顺序就重了。妙招——**规定每份不小于上一份**（递增地分），这样每种分法只有唯一的一种「从小到大」写法，天然去重（和第 5 章组合枚举的 `start` 参数一个思想）。

**剪枝在哪？**枚举当前这份的值 $v$ 时，$v$ 不能太大：后面还有若干份**每份都至少是 $v$**，所以 $v$ 至多占剩余总量除以剩余份数，即 $v \le rest / step$。循环上界写 `rest / step`，超界分支根本不会生成——这就是可行性剪枝。

**参考代码**

```cpp
#include <iostream>
using namespace std;

long long cnt = 0;

// 还要分 step 份；剩余总额 rest；每份至少 minv
void dfs(int step, int rest, int minv) {
    if (step == 1) {          // 最后一份只能拿走剩下全部
        cnt++;
        return;
    }
    // 可行性剪枝：v 不能超过 rest/step（后面每份都 ≥ v）
    for (int v = minv; v <= rest / step; v++) {
        dfs(step - 1, rest - v, v);   // 下一份 ≥ 当前这份
    }
}

int main() {
    int n, k;
    cin >> n >> k;
    dfs(k, n, 1);
    cout << cnt << endl;
    return 0;
}
```

对照样例 `7 3`：第一层 $v$ 只能取 1 或 2（$7/3=2.3$ 向下取 2）——如果允许 $v=5$，后面两份每份 ≥ 5 需要 10，早就不够了。剪枝把 $7^3$ 量级的朴素枚举压成了 4 条路径。

## 搜索优化的通用心法

| 心法 | 一句话 |
| ---- | ---- |
| 先想状态空间 | 搜索树有多大？$n!$、$2^n$ 还是 $k^n$？ |
| 找冗余 | 哪些分支明摆着没戏？（合法性 / 优于已有 / 与别人等价） |
| 早剪优于晚剪 | 条件成立的第一时间就 return，别等递归到出口 |
| 排序加快剪枝 | 贪心式排序（大的先试）常让最优性剪枝提前生效 |

!!! warning "剪枝不是万能药"

    剪枝只是「少走」，改变不了指数级的本性。数据范围到 $10^5$ 级别的题，
    剪枝救不了，得靠动态规划（第 8 章）或贪心。**搜索题的数据范围一般
    $\le 30$——看到大 n 就别往搜索想了。**

## 动手试一试

1. 数的划分不剪枝版：把循环上界改成 `rest`，比较 $n=30, k=4$ 时两版的运行速度
2. 加最优性剪枝的练习：读入 $n$ 个数（$n \le 20$），判断能否选出若干个凑出恰好 $S$。凑的过程中当前和已 $> S$ 就剪掉（要求所有数都是正整数）
3. 自然数拆分（洛谷 P2404）：输出 $n$ 的所有拆分方案（本题要求输出每个方案本身，搜索树要存路径）
4. 思考：数的划分还能再加一条「对称剪枝」吗？提示：第一份最大只能到 $n/k$，第二份最大呢？
